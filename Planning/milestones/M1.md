| Budget | A (MultiPV 5) | B | C | D | E | Worst case |
|---|---|---|---|---|---|---|
| `quick` | 250,000 | 50,000 | 50,000 | 25,000 | 25,000 | ≈ 0.65 M nodes |

| `deep` | 4,000,000 | 800,000 | 800,000 | 400,000 | 400,000 | ≈ 10.4 M nodes |

Worst case: A + B + C + 6 × D + 6 × E (five candidates plus an asked move outside A).

- Engine options: `Threads` from `--threads` (default 1), `Hash` 64 MB,
  `UCI_ShowWDL true`. `reproducible` is `threads == 1`.
- Per search: `ucinewgame`, `setoption name MultiPV value k`, `isready`/`readyok`,
  `position fen …`, `go nodes N [searchmoves …]`, read until `bestmove`.
- Per multipv index, keep the last `info` line that has `pv` and `wdl` and no
  `lowerbound`/`upperbound`. A search that ends without such a line is an
  `EngineError`.
- Fixed search order: A, B, then per candidate in MultiPV order D then E, then for an
  asked move outside A: C, D, E.
- Startup timeout 10 s (`uciok`, `readyok`). Search watchdog 120 s. Shutdown: `quit`,
  then SIGKILL after 2 s. The process starts with `fork`/`execv`, never through a
  shell.

## 4. Analysis rules

`S` = side to move, `O` = opponent. `ES` = expected score `(2W + D) / 2000` from the
engine's WDL output, kept as integer `es_units = 2W + D` (0–2000) so thresholds compare
exactly. JSON prints `es_units / 2000`.

### 4.1 Terminal positions

No legal moves: `position.terminal` is `checkmate` (in check) or `stalemate`; no
search runs (`engine.nodes_searched = 0`), `eval_white`, `threats` are null,
`candidates` is empty. Any `--move` is then illegal (exit 2). The engine is still
started, for `engine.name`.

### 4.2 Searches

| ID | From | Search | Gives |
|---|---|---|---|
| A | current position | MultiPV K = 5 | candidates, `S`'s threat (best line), `eval_white` |
| B | null move (`makeNullMove`) | single PV | `O`'s threat and its first move `t`; skipped when `S` is in check |
| C | current position | `searchmoves m` | asked move `m` not among A's lines |
| D(m) | after `m` | `searchmoves t` | does `m` parry `O`'s threat |
| E(m) | after `m`, null move | single PV | threat `m` creates |

### 4.3 Consequence of a line

For a line played from `root` by root's side to move (the threatening side):

1. Walk the first H = 6 plies. Then keep walking while the next move is a capture,
   up to H + 4 plies. `plies` = plies walked (≤ line length).
2. `material` = change in material balance for the threatening side, pawn units
   P 1, N 3, B 3, R 5, Q 9 (promotions count as the piece change).
3. `promotes` = the threatening side promoted within the walked plies.
4. `class`: `mate` when the source line has a mate score > 0 for the threatening side
   (`mate_in` = that score); else `material` when `material ≥ 1`; else `promotion`
   when `promotes`; else `positional`.
5. `rank`: mate 4, material ≥ 3 → 3, material ≥ 1 → 2, promotion 1, positional 0.

Vision §5.2's "ES swing" field is dropped: for a null-move threat it only measures the
tempo.

### 4.4 Null-move reliability

`null_move_reliable` = false when `S` has at most one piece other than king and pawns;
null when `S` is in check; true otherwise.

### 4.5 Parry test D(m)

Runs only when `O`'s threat exists with rank ≥ 2; otherwise `parries_threat` is null.

1. `t` is illegal after `m`, `m` gives check, and `t` is pseudo-legal there (or `m`
   mates): `parries = false`, test `deferred_by_check`.
2. `t` is illegal after `m` otherwise: `parries = true`, test `threat_move_illegal`.
3. Otherwise search D. The threat still works iff
   `ES_O(D) ≥ ES_O(B) − 0.03`; `parries = !works`, test `searched`.

Deviation from vision §5.3: comparing consequence ranks after `m` failed fixture F11
(the threat's class changed along the line while the outcome did not). The ES
comparison is engine truth about the same move `t`.

### 4.6 Urgency

Replaces vision §5.3 rules 2–4 (the within-class "larger or faster" rule picked the
wrong side whenever `S`, who moves first, had a forcing line):

1. `S` in check → `more_urgent = O`, rule `in_check`.
2. Both ranks < 2 → `more_urgent = null`, rule `quiet`.
3. Ranks differ → the higher side, rule `consequence_class`.
4. Equal ranks → D on A's best move: does not parry → `S`, rule `counterattack`;
   parries → `O`, rule `parry`.

### 4.7 Moves and verdicts

- `loss = max(0, ES_S(best) − ES_S(m))` in es_units.
- Thresholds (Captain's decision 2026-10-17, rescaled to SF19's WDL curve, which is about
  2.7× steeper than the scale behind Lichess's grades):

  | Verdict | Loss |
  |---|---|
  | fine | ≤ 0.03 |
  | inaccuracy | > 0.03 and < 0.13 |
  | mistake | ≥ 0.13 and < 0.27 |
  | blunder | ≥ 0.27 |

- `line`: the move's PV as SAN from the current position, ≤ 10 plies.
- `gives_check`: `m` gives check.
- `creates_threat` (E): null when `m` gives check or ends the game; otherwise a Threat
  by `S` from the position after `m` plus a null move.
- `refutation`: when the verdict is not fine, `O`'s reply line (the PV after `m`) as a
  Threat by `O` rooted after `m`; its consequence uses the line's mate score negated to
  `O`'s view. Null for fine moves.
- `fine_truncated`: A returned K lines and all K are fine (more fine moves may exist).
- Asked move: copied from A when present (`in_multipv = true`); otherwise C
  (`in_multipv = false`), then D and E as for candidates.

### 4.8 Opening names

- Table: `assets/data/openings/{a..e}.tsv` from lichess-org/chess-openings `a6189a3`
  (CC0), columns `eco`, `name`, `pgn`. Each `pgn` is replayed from the start position.
- Key: `Board::getFen(false)` (placement, side, castling, en-passant square only with a
  legal capture). Duplicate keys, malformed rows, illegal moves → `OpeningsError`
  (exit 3). Measured: 3,865 rows, 3,865 keys.
- `current`: name of the analysed position or null. `last_named`: PGN input only, the
  last named position among the mainline positions after half-moves 1..ply, with its
  ply; null otherwise. Never a guessed or nearest name.

## 5. Input

- FEN: validation per `input.hpp` (field count, characters, ranks, exactly one king
  each, no pawns on rank 1/8, side not to move not in check, castling rights
  consistent). Four-field FEN gets `0 1`.
- PGN: mainline only; comments, variations and NAGs ignored; `[FEN]`/`[SetUp]` honoured.
  `--game` is 1-based (default 1), `--ply` counts half-moves from the game's start
  position (default: final position).
- Real annotated files: `read_games` (`input.hpp`) reads every game, with comments
  (brace and `;`, across lines, inside and before variations), nested variations, NAGs
  and `12...` move numbers. Smoke: all 580 games of the Captain's world-championship
  file in `Resources/` (git-ignored). `load_pgn` shares this parser.
- `chesswhy-pgn FILE [--game N]` prints one TSV row per mainline half-move:
  `game ply move_number side san uci nags fen_before fen_after` (header row first;
  `nags` comma-separated, empty if none). `chesswhy-pgn --games FILE` prints
  `game white black event date result plies`. Errors: `chesswhy-pgn: error: <message>`,
  exit 2. Comment text is never printed.
- Moves: SAN (check suffixes optional) or UCI, including castling, en passant and
  promotions.

## 6. CLI

```text
chesswhy (--fen FEN | --pgn FILE [--game N] [--ply N]) [--move MOVE]
         [--level beginner|club|advanced] [--budget quick|standard|deep]
         [--json] [--no-llm] [--threads N] [--engine PATH] [--openings DIR] [--help]
```

- Defaults: `--engine <assets>/engines/stockfish`, `--openings <assets>/data/openings`,
  `<assets>` = compile-time `CHESSWHY_ASSETS_DIR`.
- `--json` prints the report; otherwise the template text. `--no-llm` is accepted and
  changes nothing in M1. `--level` is recorded in the report; the M1 template ignores it.
- Order in `run`: parse and validate all input, load openings, start the engine,
  analyse, print. Nothing is printed to `out` on error.
- Errors: one line on `err`, `chesswhy: error: <message>`; exit 2 for usage/FEN/PGN/move
  errors, 3 for engine or asset errors. Message fragments that tests rely on:
  `invalid FEN`, `illegal move`, `ambiguous move`, `cannot parse move`,
  `exactly one of --fen or --pgn`, `game N`, `move N`, `ply N`, and the offending
  token, path or flag.

## 7. Report v1

Schema: `schema/report.v1.schema.json`; data model: `report.hpp`. Every fact carries
its provenance field as defined in the schema (`engine` for searched values, `rule` for
computed classifications). Key order follows the schema; output is byte-identical for
identical input and budget with `Threads=1`.

## 8. Template rendering

`render::text` prints, in this order: position (side to move, check, terminal state,
evaluation as ES percentage plus cp or mate), threats with consequences and the urgency
rule, candidates with verdicts and their parry/create facts, the asked move with its
refutation, the opening name with its dataset. Each fact line ends with its provenance
in brackets. It prints only report fields, no chess claim of its own. Golden-text tests
in WP4 pin the wording.

## 10. Build layout

- `cmake --preset release` → `build/release` (Release, `compile_commands.json` for
  clangd); `cmake --preset asan` → `build/asan` (Debug, ASan + UBSan, timing check off).
- Interface targets (top level): `chess_library`, `chesswhy_headers` (our include dir,
  chess-library, nlohmann_json), `chesswhy_warnings` (`-Wall -Wextra -Wpedantic
  -Werror`), `chesswhy_paths` (`CHESSWHY_ASSETS_DIR`, `CHESSWHY_SOURCE_DIR`).
- Each module: `src/<module>/CMakeLists.txt` defines static library
  `chesswhy_<module>`; `tests/<module>/CMakeLists.txt` defines Catch2 tests
  (`Catch2::Catch2WithMain`, `catch_discover_tests(... PROPERTIES LABELS <label>)`).
- The top-level `EXISTS` guards around modules are temporary; WP6 removes them.
- llama.cpp stays out of the build in M1.
- Schema validation: CTest runs `${CHESSWHY_PYTHON} tools/validate_report.py
  schema/report.v1.schema.json <report.json>...`. `CHESSWHY_PYTHON` defaults to
  `.venv/bin/python`; a missing venv fails the test.
